You’re right—this is a brutal UX. I dug through EDG-QUOTING and found the culprit(s):

What’s causing the “reloading while typing”

Your line-item inputs get reset by a background refetch while the user is typing.
In LineItemsTable you intentionally guard against resetting local input state when users are editing:

// don't reset when editing or saves pending
if (Object.keys(debounceTimers.current).length > 0 || activeInputs.current.size > 0) {
  return;
}


…but activeInputs is never populated on focus. It’s only cleared on blur. So when /api/quotes/:id is invalidated elsewhere (e.g., header/summary edits, or background refetch), lineItems props refresh, your useEffect([lineItems]) runs, and it re-seeds inputs, blowing away what the user just typed.

Other parts of the page trigger invalidations for the whole quote.
QuoteHeader / QuoteSummary both mutate /api/quotes/:id and then invalidate the same key, which refetches the quote (including line items) and trips the reset described above.

Minimal fixes to stop the churn
A) Track focused fields so the table won’t reset while typing

Add onFocus to every editable input to mark it “active”, and remove in onBlur (you already remove on blur):

// inside the row render for each editable field
<Input
  value={getCurrentValue(item.id, 'unitPrice')}
  onChange={(e) => handleFieldChange(item.id, 'unitPrice', e.target.value)}
  onFocus={() => activeInputs.current.add(`${item.id}-unitPrice`)}
  onBlur={() => handleFieldBlur(item.id, 'unitPrice')}
  data-testid={`input-unit-price-${item.id}`}
/>


You already have: activeInputs.current.delete(key) in handleFieldBlur and the guard in useEffect([lineItems]). You just need the onFocus add so the guard actually works. 

line-items-table

Do the same for: description, quantity, markupValue, and the Select for markupType.

B) Tame background refetches while editing

In quote-builder.tsx, adjust the quote query to avoid surprise refetches during editing:

const { data: quote, isLoading, error } = useQuery<QuoteWithDetails>({
  queryKey: [`/api/quotes/${quoteId}`],
  enabled: !isNewQuote,
  staleTime: 60_000,
  refetchOnWindowFocus: false,
  refetchOnReconnect: false,
});


This keeps React Query from refetching just because the window re-focused, etc.

C) Be selective with invalidations

Line items: you already skip broad invalidations on single-field updates (good). Keep that. 

line-items-table

Header / Summary: prefer queryClient.setQueryData([/api/quotes/${id}], updater) for simple field changes like taxRate, discount, shipping, or notes instead of invalidating immediately. If you do need to invalidate, consider deferring until blur (you already blur-save in QuoteSummary) which plays nicely with A).

Why this matches the symptoms

Users say “as soon as they delete or add a number it reloads.” With no onFocus tracking, any refetch (or a sibling component update that invalidates the quote) causes the table’s useEffect([lineItems]) to reseed the inputs. Cursor jumps, value reappears, and they can’t finish typing. The code already tries to prevent that; it just never flips the “I’m editing right now” switch.
