Your tailwind.config.ts file and index.css file show you are using the correct class-based dark mode with CSS variables.The readability problem is likely not in your setup, but in how you are using colors in your components.Here’s how to fix the readability issues and implement the theme toggle.How to Fix ReadabilityThe core issue is almost certainly the use of static colors (e.g., bg-white, text-black, or your custom bg-edg-grey) instead of semantic, theme-aware colors (e.g., bg-background, text-foreground).Your index.css file defines two sets of variables::root: These are your light mode colors..dark: These are your dark mode colors.When you use Tailwind classes like bg-background or text-foreground, Tailwind applies the CSS variable (e.g., var(--background)). This variable automatically gets the correct color depending on whether the .dark class is active.Colors like bg-white or your custom bg-edg-light-grey do not have a dark mode variant, so they will look wrong in a dark theme.The Solution: Use Semantic ColorsYou must refactor your components to use the semantic classes you have already defined. This will fix readability and make your components theme-aware instantly.Instead of This (Static)Use This (Theme-Aware)bg-white or bg-gray-50bg-backgroundtext-black or text-gray-900text-foregroundbg-gray-100bg-muted or bg-secondarytext-gray-600text-muted-foregroundAny component "box" or "panel"bg-card text-card-foregroundButtonsbg-primary text-primary-foregroundBordersborder-borderInputsbg-input text-foreground border-inputYour main task is to audit your components (files in client/src/) and replace static colors with these theme-aware classes.How to Add a Dark/Light Theme ControlYour config is already set up for this with darkMode: ["class"]. You just need a component to add or remove the .dark class from the <html> tag.You can create a new component like client/src/components/theme-toggle.tsx and add it to your App.tsx or header.Example ThemeToggle.tsx ComponentHere is a simple, complete React component to manage the theme:TypeScript// client/src/components/theme-toggle.tsx
import { useEffect, useState } from "react";
import { Button } from "./ui/button"; // Assuming you have a button component
import { Moon, Sun } from "lucide-react"; // Example icons

type Theme = "dark" | "light" | "system";

export function ThemeToggle() {
  // Default to 'system' or 'light'
  const [theme, setTheme] = useState<Theme>(() => {
    const savedTheme = localStorage.getItem("theme") as Theme;
    return savedTheme || "light"; 
  });

  // Effect to apply the theme
  useEffect(() => {
    const root = window.document.documentElement;
    root.classList.remove("light", "dark");

    let activeTheme = theme;

    if (theme === "system") {
      // Check system preference
      const systemIsDark = window.matchMedia(
        "(prefers-color-scheme: dark)"
      ).matches;
      activeTheme = systemIsDark ? "dark" : "light";
    }

    // Apply the active theme class
    root.classList.add(activeTheme);
    
    // Save user's explicit choice (not the resolved 'activeTheme')
    localStorage.setItem("theme", theme);
  }, [theme]);

  const toggleTheme = () => {
    setTheme(theme === "light" ? "dark" : "light");
  };

  return (
    <Button variant="ghost" size="icon" onClick={toggleTheme}>
      {theme === "light" ? (
        <Sun className="h-[1.2rem] w-[1.2rem]" />
      ) : (
        <Moon className="h-[1.2rem] w-[1.2rem]" />
      )}
      <span className="sr-only">Toggle theme</span>
    </Button>
  );
}
How This WorksState: It keeps track of the user's choice (light or dark).localStorage: It saves the user's preference so it persists across page reloads.useEffect: When the theme state changes, this effect runs:It gets the <html> tag (document.documentElement).It removes any old theme class.It adds the new theme class (.dark or .light).By adding this component, you give users control, and because you've refactored your components to use semantic colors, your entire app will now respond correctly.
