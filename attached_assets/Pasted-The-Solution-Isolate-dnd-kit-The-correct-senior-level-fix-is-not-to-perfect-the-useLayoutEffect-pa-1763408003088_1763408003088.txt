The Solution: Isolate dnd-kit
The correct, senior-level fix is not to perfect the useLayoutEffect patch; it's to prevent the DOM remount from happening in the first place.

You must stop the input's pointer events from ever reaching dnd-kit. This isolates the input, allowing the user to type, while still allowing the drag handle to initiate a drag.

This fix was noted as "Optional but nice" in your Pasted-Got-it...txt file, but it is, in fact, the essential solution to this specific bug.

You need to add onPointerDown={(e) => e.stopPropagation()} to every single <Input> inside your SortableLineItemRow. This prevents the event from bubbling up to the <tr> and triggering dnd-kit's listener.

By implementing this, the dnd-kit library will no longer be triggered by clicks inside the inputs. The onChange event will still fire, the state will update, and React will re-render, but because dnd-kit is not adding new attributes, React will correctly diff the <tr>, see that only the input's value has changed, and perform a simple DOM update without remounting the element.

This solves the root cause, stabilizes the DOM, and makes your useLayoutEffect patch (the "focus-restorer") entirely unnecessary. You can safely remove the useLayoutEffect hook (lines 191-218) and the activeKeyRef/caretRef refs after applying this fix, as native browser focus will no longer be lost.
