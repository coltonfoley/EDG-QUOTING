Findings
LineItemsTable defines SortableLineItemRow inside the component body (const SortableLineItemRow = memo(...)). Because that function is recreated every render, React treats it as a brand‑new component type each time LineItemsTable re-renders, so every row (and its inputs) is unmounted/remounted on every keystroke. This resets focus/caret to the end before the effect can restore it.

Proposed Fix
Hoist SortableLineItemRow out of LineItemsTable (ideally into its own file) or wrap its creation in useMemo so React sees a stable component type between renders. Pass the necessary handlers (getCurrentValue, handleFieldChange, handleFieldBlur, etc.) as props. Once the row component isn’t recreated each render, inputs stop remounting and the cursor stays where the user left it without extra hacks.
After the component type is stabilized you can keep React.memo (to avoid rerendering rows whose props didn’t change) and simplify/remove the focus-restoration effect because the DOM nodes will persist while typing.
No backend or query changes are required—the current quote query (client/src/pages/quote-builder.tsx) already has calm staleTime/refetch options, so solving the component identity issue will resolve the cursor jumping behavior.
