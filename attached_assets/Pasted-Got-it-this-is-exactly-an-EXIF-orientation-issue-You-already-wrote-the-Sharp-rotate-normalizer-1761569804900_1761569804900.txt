You already wrote the Sharp .rotate() normalizer (perfect), but since uploads are skipping your server and going straight to object storage, that code never runs. Here’s a clean way to wire it in (plus a client-side safety net so PDFs are always correct).

Server-side: make normalization part of the upload flow (best)
Option A — Route uploads through your server (recommended)

If you can swap from direct-to-bucket to server-mediated uploads, do this once and it solves all future image weirdness.

Express + Multer (memory) → Sharp → Storage

// server/uploads.ts
import express from 'express';
import multer from 'multer';
import { normalizeImage } from './quoteImageUtils'; // your existing function with .rotate()
import { putObject } from './storage'; // wrap S3/Supabase/GCS here; show examples below

const router = express.Router();
const upload = multer({ storage: multer.memoryStorage() });

router.post('/image', upload.single('file'), async (req, res) => {
  try {
    if (!req.file) return res.status(400).json({ error: 'Missing file' });

    // 1) normalize EXIF & resize policy (inside/cover) in normalizeImage()
    const normalized = await normalizeImage(req.file.buffer, { maxW: 2400, maxH: 1800 });

    // 2) choose a key (e.g., prefix by quoteId/userId)
    const key = `uploads/${Date.now()}-${req.file.originalname.replace(/\s+/g, '_')}`;

    // 3) upload to your storage
    const publicUrl = await putObject(key, normalized, req.file.mimetype || 'image/jpeg');

    return res.json({ key, url: publicUrl });
  } catch (e: any) {
    console.error(e);
    return res.status(500).json({ error: 'Upload failed' });
  }
});

export default router;


Storage adapter example (S3):

// server/storage.ts
import { S3Client, PutObjectCommand } from '@aws-sdk/client-s3';

const s3 = new S3Client({ region: process.env.AWS_REGION });
const BUCKET = process.env.S3_BUCKET!;

export async function putObject(key: string, body: Buffer, contentType: string) {
  await s3.send(new PutObjectCommand({
    Bucket: BUCKET,
    Key: key,
    Body: body,
    ContentType: contentType,
    ACL: 'public-read', // if you need a public URL
  }));
  return `https://${BUCKET}.s3.amazonaws.com/${encodeURIComponent(key)}`;
}


Then point your client uploader to POST /api/uploads/image with FormData.

Option B — Keep direct uploads, then server “post-process”

If you must keep presigned/direct uploads, add a normalization step immediately after the client finishes uploading (or trigger on the server when you receive the uploaded key).

API to normalize in place:

// server/normalize-after-upload.ts
import { getObjectBuffer, putObject } from './storage';
import { normalizeImage } from './quoteImageUtils';

export async function normalizeImageAtKey(key: string, contentTypeFallback = 'image/jpeg') {
  const { buffer, contentType } = await getObjectBuffer(key);
  const normalized = await normalizeImage(buffer, { maxW: 2400, maxH: 1800 });
  await putObject(key, normalized, contentType || contentTypeFallback);
  return true;
}


Client flow:

Upload directly (presigned URL).

Call POST /api/uploads/normalize { key }.

Server reads the object, runs .rotate(), writes back (same key).

Invalidate CDN cache if you use one.

(Even better): use a bucket event → webhook/Lambda to normalize on ObjectCreated, then write to normalized/… and have your app use that path.

Client-side safety net (works even if a raw image slips through)

For PDF generation, the browser’s <img> usually applies EXIF, but Canvas and PDF libs don’t. Use createImageBitmap(blob, { imageOrientation: 'from-image' }) so you always get pixel data with the orientation applied before you convert it to dataURL / embed in jsPDF/pdf-lib.

// client/src/lib/image-orientation.ts
export async function loadCorrectedImageBitmap(fileOrBlob: File | Blob): Promise<ImageBitmap> {
  // Modern browsers: respects EXIF Orientation
  if ('createImageBitmap' in window) {
    try {
      const bmp = await createImageBitmap(fileOrBlob, { imageOrientation: 'from-image' as any });
      return bmp;
    } catch { /* fallback below */ }
  }
  // Fallback: plain Image
  const url = URL.createObjectURL(fileOrBlob);
  const img = await new Promise<HTMLImageElement>((res, rej) => {
    const i = new Image();
    i.onload = () => res(i);
    i.onerror = rej;
    i.src = url;
  });
  // draw to canvas as-is (may be rotated if browser didn’t auto-apply)
  const canvas = document.createElement('canvas');
  canvas.width = img.naturalWidth;
  canvas.height = img.naturalHeight;
  const ctx = canvas.getContext('2d')!;
  ctx.drawImage(img, 0, 0);
  const blob = await new Promise<Blob>((resolve) => canvas.toBlob(b => resolve(b!), 'image/jpeg', 0.92));
  return await createImageBitmap(blob);
}


Using it in your PDF pipeline (jsPDF example):

import { loadCorrectedImageBitmap } from './image-orientation';

async function addImageToPdf(doc: jsPDF, fileOrBlob: Blob, box: { x: number; y: number; w: number; h: number }) {
  const bmp = await loadCorrectedImageBitmap(fileOrBlob);
  // convert bitmap → canvas → dataURL
  const canvas = document.createElement('canvas');
  canvas.width = bmp.width;
  canvas.height = bmp.height;
  const ctx = canvas.getContext('2d')!;
  ctx.drawImage(bmp, 0, 0);
  const dataUrl = canvas.toDataURL('image/jpeg', 0.9);

  // (Use your existing aspect-fit helper here)
  const { w, h } = getAspectFitBox(bmp.width, bmp.height, box.w, box.h);
  const { x, y } = getCenteredOrigin(box.x, box.y, box.w, box.h, w, h);
  doc.addImage(dataUrl, 'JPEG', x, y, w, h);
}


pdf-lib variant: create an ArrayBuffer from the canvas blob and embedJpg that buffer; same sizing logic.

One more thing: lock a global image policy

EXIF: always normalize (server) or createImageBitmap(...from-image) (client).

Aspect ratio: always fit or cover (pick one) — never stretch.

CDN: if you overwrite keys, make sure to purge/invalidate so the corrected image shows in proposals.

TL;DR implementation plan

Wire your existing normalizeImage into the upload path (Option A preferred).

Add a post-upload normalizer if direct uploads must stay (Option B).

Add createImageBitmap(...{ imageOrientation: 'from-image' }) to the PDF image loader so you’re safe even if a raw image sneaks through.

Keep the aspect-fit math you and I outlined earlier to prevent distortion.
