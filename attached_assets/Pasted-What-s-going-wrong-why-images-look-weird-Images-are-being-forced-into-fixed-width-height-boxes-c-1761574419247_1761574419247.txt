What’s going wrong (why images look weird)

Images are being forced into fixed width/height boxes (client or server), so the aspect ratio gets distorted.

Some images have EXIF orientation that isn’t normalized first (portrait shows up sideways/tall and gets crushed).

If you’re pre-resizing, resize(width,height) without a fit mode will stretch.

The fix (drop-in changes)
A) Server: normalize uploads with Sharp (preserve ratio + auto-orient)

In server/quoteImageUtils.ts, make sure you’re doing this when you process uploads:

// server/quoteImageUtils.ts
import sharp from 'sharp';

export async function normalizeImage(buf: Buffer, opts?: { maxW?: number; maxH?: number }) {
  const maxW = opts?.maxW ?? 2400; // pick a sensible cap for PDFs
  const maxH = opts?.maxH ?? 1800;

  const out = await sharp(buf)
    .rotate() // auto-orient based on EXIF
    .resize({
      width: maxW,
      height: maxH,
      fit: 'inside',          // PRESERVE aspect ratio
      withoutEnlargement: true,
    })
    .jpeg({ quality: 85, mozjpeg: true }) // or .png() if you need lossless
    .toBuffer();

  return out;
}


If you want identical “tiles” with no empty bars, change to:

.resize({ width: maxW, height: maxH, fit: 'cover', position: 'attention' })


(That will crop a bit instead of letterboxing; pick one style globally so proposals look consistent.)

B) Client: compute aspect-fit before embedding in the PDF

Whether you’re using jsPDF or pdf-lib, always compute the scaled width/height relative to the box you want to fill on the page.

Add these helpers (e.g., in client/src/lib/pdf-image-pipeline.ts or a shared util):

export function getAspectFitBox(
  imgW: number,
  imgH: number,
  boxW: number,
  boxH: number
) {
  const scale = Math.min(boxW / imgW, boxH / imgH);
  return {
    w: imgW * scale,
    h: imgH * scale,
  };
}

export function getCenteredOrigin(boxX: number, boxY: number, boxW: number, boxH: number, w: number, h: number) {
  const x = boxX + (boxW - w) / 2;
  const y = boxY + (boxH - h) / 2;
  return { x, y };
}


Then, where you currently do doc.addImage(...) / pdfPage.drawImage(...), replace any hardcoded width/height with aspect-fit sizing, e.g.:

// Example with jsPDF:
const pageW = doc.internal.pageSize.getWidth();
const pageH = doc.internal.pageSize.getHeight();
const margin = 24;
const boxW = pageW - margin * 2;
const boxH = 240; // e.g., “gallery tile” height on your layout

const { w, h } = getAspectFitBox(img.naturalWidth, img.naturalHeight, boxW, boxH);
const { x, y } = getCenteredOrigin(margin, 120 /* top of section */, boxW, boxH, w, h);

doc.addImage(imgData, 'JPEG', x, y, w, h);  // no distortion now


If you’re using pdf-lib:

const img = await pdfDoc.embedJpg(bytes); // or embedPng
const { width: iw, height: ih } = img.size();
const { w, h } = getAspectFitBox(iw, ih, boxW, boxH);
const { x, y } = getCenteredOrigin(boxX, boxY, boxW, boxH, w, h);

page.drawImage(img, { x, y, width: w, height: h });

C) If any HTML → PDF sections exist

If some sections render HTML (html2canvas/Puppeteer), ensure images use contain not stretch:

<img style="
  display:block;
  max-width:100%;
  height:auto;
  object-fit:contain;  /* or cover if you prefer uniform crop */
  aspect-ratio:auto;   /* avoids forced aspect */
" />


Avoid specifying both width and height on the <img> tag; that’s the #1 distortion source.

Pick a global visual policy (important)

Decide once for the whole proposal:

Contain (no crop): everything shows, may get white bars (letterboxing) inside the tile → set Sharp fit: 'inside' and PDF to aspect-fit.

Cover (cropped but uniform tiles): fills the tile; edge/corner crop → set Sharp fit: 'cover' and PDF to center-crop inside fixed boxes.

Either choice looks clean as long as it’s consistent across the document.

Where to patch in your repo (concrete)

Normalize uploads: server/quoteImageUtils.ts (ensure rotate() and fit: 'inside' | 'cover').

PDF placement logic: client/src/lib/pdf-image-pipeline.ts and likely client/src/lib/pdf-sections.ts (swap any fixed width/height with the getAspectFitBox approach above).

If a branded cover uses a hero image: check client/src/lib/pdf-branded-sequence.ts for any hardcoded sizes and replace with aspect-fit or cover logic.
