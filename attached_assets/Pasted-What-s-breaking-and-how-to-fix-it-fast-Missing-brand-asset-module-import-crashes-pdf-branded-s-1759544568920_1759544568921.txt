What’s breaking (and how to fix it fast)

Missing brand asset module (import crashes)

pdf-branded-sequence.ts imports BRAND_COVER_JPG, BRAND_LOGO_PNG, BRAND_BACK_PAGE_PNG from ./pdf-brand-assets, but I don’t find that file in the repo (spec says “create it” with placeholders). If the file is missing or still has REPLACE, jsPDF.addImage will throw “Invalid image/Unsupported data URL,” and the generator dies.

// client/src/lib/pdf-brand-assets.ts

export const BRAND_LOGO_PNG  = 'data:image/png;base64,<VALID_BASE64...>';

(You can use any temporary 1×1 px image for now so generation never hard-crashes; replace later with real assets.)
The orchestrator expects these to exist.

Font name mismatch (hard crash on first text draw in sections)

In sections, you’re calling pdf.setFont('Barlow-SemiBold', 'normal'), but in the classic generator you register only 'Barlow' (normal/bold). That means the branded flow tries to use a font family that doesn’t exist → jsPDF throws (“Font does not exist”).

Two safe options (pick one):

Option A (quick): change all section font calls to the registered name:

// client/src/lib/pdf-sections.ts
pdf.setFont('Barlow', 'bold');   // instead of 'Barlow-SemiBold'
pdf.setFont('Barlow', 'normal'); // where 'Barlow-Regular' was used


Spots to change include headers in Project Details, Renderings, Line Items, Contract, and footer text.

Option B (proper): register the same names you use:

// after addFileToVFS/addFont in your PDF setup
pdf.addFileToVFS('Barlow-Regular.ttf', barlowRegularBase64);
pdf.addFont('Barlow-Regular.ttf', 'Barlow-Regular', 'normal');
pdf.addFileToVFS('Barlow-SemiBold.ttf', barlowSemiBoldBase64);
pdf.addFont('Barlow-SemiBold.ttf', 'Barlow-SemiBold', 'normal');


Then the section code works unchanged.

Image pipeline assumptions (invalid/empty data URLs)

The sections call addImage(coverDataUrl, 'PNG', ...) but the asset might be JPEG or missing, and there’s no guard. If the data URL prefix doesn’t match the declared format (or is empty), jsPDF throws. Add a small format detector or always pass the correct format.

pdf-sections

Fix:

// tiny helper in pdf-sections.ts
const fmt = (dataUrl: string) => dataUrl.startsWith('data:image/png') ? 'PNG' : 'JPEG';

// when adding images
pdf.addImage(coverDataUrl, fmt(coverDataUrl), 0, 0, pageW, pageH);


Also ensure your three brand constants are valid data URLs (see #1).
