this error maps straight to your image normalizer. The crash happens before jsPDF runs: your client tries to fetch() an image URL and the request dies (TypeError: Failed to fetch), so the whole PDF step aborts.

Root cause (why it’s failing)

Your normalizer always does fetch(src, { credentials: 'include' }) for every image source (including data: and blob: URLs, and external object-storage URLs). That triggers CORS/preflight or unsupported-scheme failures, which surface as TypeError: Failed to fetch.

In the branded generator flow you normalize gallery/cover images from preview (temp = blob:; persistent = proxied or absolute URL). The “persistent” path sometimes returns an absolute external URL that is not always proxied, so the browser blocks it on CORS during fetch. 

simple-proposal-generator

You do have a server-side image proxy (/api/image-proxy) to bypass CORS, but your getProxiedImageUrl only proxies storage.replit.com instead of “any non-same-origin URL,” so other hosts slip through and still get fetched cross-origin on the client.

In at least one place you double-fetch persistent images in the React component (again with credentials: 'include') to turn them into data URLs, which can hit the same CORS issue.

3) Don’t let one bad image kill the whole PDF

File: client/src/components/simple-proposal-generator.tsx
In your generate handler (right before calling generateBrandedSequencePDF), normalize images like this:

// Build renderImages for the branded flow, but don't crash if one fails
const renderImages = (
  await Promise.allSettled(
    productRenderings.map(img => normalizeImageToDataUrl(img.preview))
  )
).flatMap(r => (r.status === 'fulfilled' ? [r.value] : []));


Optionally show a soft toast when some images fail, but still generate the PDF. (Your component already imports normalizeImageToDataUrl; this is a small change in usage.)
